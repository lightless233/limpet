# Limpet 立项书

## 项目目标

Limpet 是一个面向个人开发者的网页终端。在 Windows 电脑上打开 H5，进入项目目录并启动 Codex 或其他 CLI。离开电脑后，用手机打开同一套 H5，接回原来的终端，查看进度并继续操作。

终端运行在 WSL 里，接续范围仅限 Limpet 创建的终端。电脑和手机共享的是同一个正在运行的 Shell 和其中的程序，切换设备时可以保留程序的当前状态。

## 第一阶段

- **打开终端。** WSL 内的 Go 服务提供 H5。用户在页面创建并打开一个由 Limpet 管理的终端，在 Shell 里进入项目目录。首版以一个可接续的终端为起点。
- **操作终端。** H5 展示实时输出，转发输入、粘贴和窗口尺寸变化。手机上可以发送 `Ctrl+C`、`Esc` 和方向键等常用终端按键。
- **换设备继续。** 关掉电脑上的页面后，终端内的程序继续执行。手机按原终端 ID 接续并看到当前画面。手机切网或刷新页面后也可以接回该终端。
- **远程访问。** Windows 和手机的日常入口使用同一个 HTTPS 地址，终端连接走 WSS。Cloudflare Access 保护页面、会话 API 和 WebSocket 握手，Tunnel 将请求转发给 WSL 服务。本地开发可直接使用 `localhost`。

## 架构

```text
[Windows H5 / 手机 H5]
           |
      HTTPS / WSS
           |
[Cloudflare Access + Tunnel]
           |
   [WSL 内的 Go 服务] <--> [tmux] <--> [Shell / CLI]
```

Go 服务负责创建会话、提供终端 ID 和处理客户端接入。HTTP 用于加载页面和管理会话，WebSocket 在浏览器与 `tmux` 客户端之间转发终端输入、输出和尺寸。

`tmux` 持有 Shell 和终端画面。浏览器断开时，Go 服务释放该次连接，`tmux` 中的程序继续运行。重新连接时，Go 服务接入原会话，由 `tmux` 重绘当前画面。

终端以 WSL 普通用户身份运行，具备该用户的命令执行权限，远程入口仅授权本人使用。远程访问依赖 Windows 保持唤醒、WSL 和服务持续运行。WSL 退出会结束其中的终端进程。

## 技术选型

| 部分 | 选型 |
| --- | --- |
| 后端 | Go，使用标准库 `net/http` 和 `http.ServeMux` 提供页面与 API，使用 `github.com/coder/websocket` 处理终端连接 |
| 终端宿主 | WSL 内的 `tmux`，管理 Shell、终端画面和断开后的进程生命周期 |
| 前端 | Vue 3、TypeScript、Vite、Tailwind CSS 4，按需引入 `shadcn-vue` 的基础组件 |
| 网页终端 | `wterm`（`@wterm/vue`）。首轮用 `@wterm/ghostty` 验证 Codex 全屏界面和手机输入 |
| 远程入口 | Cloudflare Access + Tunnel |

## 第一阶段验收

1. 在 Windows 打开 H5，进入指定目录，在终端里启动 Codex 并执行一个在页面关闭后仍会继续输出的任务。
2. 关闭电脑端页面，使用手机蜂窝网络登录并选中原终端。确认同一个 Codex 进程还在，手机可以看到断开期间产生的输出，并继续输入。
3. 在手机上检查中文输入、粘贴、方向键、`Esc` 和 `Ctrl+C`。弹出软键盘后，当前输入和输出仍清晰可见，Codex 界面随窗口尺寸变化正常重绘。
4. 手机切网后重新打开原终端，确认仍接入同一个会话。未登录时，远程入口无法创建或连接终端。

## 后续方向

- **Windows 桌面入口。** 用桌面窗口加载同一套 H5。第一阶段可用 Windows 浏览器验收，桌面外壳形态后续确定。
- **聊天模式。** 根据实际使用情况，决定哪些操作需要聊天界面，以及首批接入哪些 Harness。模型设置、审批和工具过程等能力按原生接口逐项确定。
