# Spec 001：tmux 会话接续与终端会话列表

- 日期：2026-11-22
- 状态：待评审
- 来源：`docs/project-charter.md` 第一阶段「换设备继续」「操作终端」；会话讨论（2026-11-22）：会话列表 = 任务管理的最小形态，任务由人管理

## 背景与目标

当前终端为直接 PTY：WS 断开即结束 Shell，换设备接续无从谈起。本工作项把终端宿主替换为 tmux，让 Shell 与画面常驻，浏览器只承载视图；同时提供会话列表（新建/接续/重命名/关闭），作为多任务并行的最小产品形态。

完成后，「打开多个终端、各跑任意 harness（Codex 等）、手机接续任意一个」即为可用流程，且不引入任何任务台账、通知或聊天层。

## 语义变更（需要评审确认）

**「WS 断开即结束会话」被废止。** 新语义：WS 断开只结束接入视图（tmux 客户端进程），会话与 Shell 常驻，直到用户显式关闭或在 Shell 内退出。

**「未接入不遗留 Shell」的表述被修订。** 会话创建即启动 Shell（存在于 tmux 中），并立即出现在列表里——这是有意为之的产品行为（新建 = 建任务），不是泄漏。此前的验收项（启动失败/断开后的回收）仍全部成立，只是对象从「Shell 进程」变为「tmux 会话条目」。

## 会话模型与状态归属

- **一个 Limpet 会话 = 一个 tmux session，1:1，不可拆分。** tmux 内部的 window/pane 归用户自行使用，Limpet 不感知。
- **会话 ID 即 tmux session 名**（tmux 名即身份）：列表、接入、关闭、重命名都以它寻址；无独立映射表。tmux 是常驻状态的唯一事实来源，Go 服务重启不丢会话，列表从 tmux 重建。
- **tmux 使用独立 socket（`-L limpet`）与独立配置文件**，与用户个人 tmux 服务隔离：互不影响配置，用户的 `kill-server` 不会波及 Limpet 会话。
- 接入状态（claimed、客户端进程）是运行时信息，归属 Go 进程内存，重启后视为「未接入」。

## 帧协议（不变）

沿用现有协议，直接 PTY 的子进程替换为 tmux 客户端进程，其余不动：

- 客户端 → 服务端：二进制帧 = 终端输入；文本帧 = 控制 JSON（`resize`）。
- 服务端 → 客户端：二进制帧 = 终端输出；文本帧 = `{"type":"ready"}`。
- 启动时机不变：Accept 后等**首条有效尺寸消息**再 spawn tmux 客户端（`-x/-y` 传入初始尺寸）；3s 未收到按 URL query 兜底；启动前二进制输入以 1008 `terminal not ready` 拒绝；spawn 成功先发 ready。
- 单接入不变量：同一会话同时只允许一个 WS 客户端（409）。

## 需要的行为

### 创建

- `POST /api/term`，可选 `name`。创建即 `tmux new-session`（Shell 立即启动），会话立即出现在列表。
- 名称：默认自动生成（随机短 id）；用户可后续重命名。tmux 不允许 `:` 和 `.` 出现在 session 名中，服务端校验并拒绝非法字符；重名返回 409（客户端可改名重试，服务端不做自动后缀——任务名是用户语义，静默改名不可取）。
- 名称长度上限 100 字符（UTF-8 计）。

### 列表

- `GET /api/term` → 会话数组：`{id(=名), created(创建时间), attached(是否有活跃客户端)}`。数据从 tmux 实时查询（`list-sessions`），不维护影子列表。
- 顺序：创建时间倒序（最近创建在前）。

### 接入与接续

- `GET /api/ws/term/{id}`：会话存在 → WS 升级；不存在 → 404。已有客户端 → 409。
- 首次创建后的接入与后续接续走同一入口：向 tmux 发起客户端进程（新会话 `new-session`，已存在 `attach`）。tmux 依据客户端尺寸自动调整会话尺寸并重绘当前画面。
- **接入回放**：每次接入（首次与接续）时，服务端先按精确会话名解析活动 pane ID，再捕获该 pane 可见屏**之前**的历史（最多 10000 行，含颜色转义），换行补齐 CR（回放字节绕过 tty 的 onlcr），并在 ready 之后、实时输出之前回放给浏览器。回放后，浏览器滚动缓冲内可用原生滚动与选中复制浏览断开前的内容——copy mode 只是终端内部的底层兜底，不作为网页端翻历史的手段。捕获失败降级为空历史，实时输出不受影响。
- 断开期间 Shell 的所有输出（含全屏程序状态）由 tmux 保持，接续时整屏可见；其滚动历史按上述回放机制进入浏览器。
- 浏览器滚动缓冲与回放深度对齐：10000 行。

### 断开与关闭（关键区别）

- **WS 断开**：仅终止 tmux 客户端进程。会话、Shell、画面状态全部保留。前一客户端断开与会话存活之间不得有任何终止动作。
- **显式关闭**：`POST /api/term/{id}/close` → `tmux kill-session`，Shell 终止，列表移除。前端需确认后调用。
- **Shell 内退出**（exit / tmux kill-server 等）：会话自然消失，下次列表与接入调用如实反映（404）；正在接入的客户端会话结束（沿用现有会话结束监视器语义）。

### 重命名

- `POST /api/term/{id}/rename`，body `{name}`。校验规则同创建；重名 409。重命名对活跃客户端透明（tmux 内部完成）。

### 前端（移动端优先，PC 同等支持）

移动浏览器是第一目标环境（charter 的核心场景就是手机接续）：所有交互可用触控完成，不得依赖 hover；桌面端获得同等功能，差异仅限响应式布局。

- **会话列表（移动端即首页）**：单列布局，整行点击进入终端；行内展示名称、创建时间、接入状态；重命名与关闭为行内图标按钮，触达目标 ≥ 44×44。
- **新建 / 重命名**：底部弹层输入名称（新建可空），软键盘弹出时输入框保持可见。
- **终端页**：现有组件生命周期保留（每会话重建 core/组件、首屏尺寸从实例读取、ready 前输入闸门 + inert）；顶部提供显式「返回列表」入口（移动端没有其他逃逸路径），返回不断开后台会话。
- **移动按键栏**：移动视口下终端页提供常用按键——Esc、Ctrl 组合键（Ctrl 为粘性修饰键）、Tab、方向键、Enter，以终端输入形式发送。这是 charter 第一阶段「手机上可以发送 Ctrl+C、Esc 和方向键」的落地。
- **安全区**：列表与终端页适配系统安全区（刘海/底部横条），内容与操作不被遮挡。
- 列表数据拉取时机：进入列表页 + 增删改操作后。

## 约束与边界

- tmux 不存在或 socket 不可用时：创建/列表/接入返回明确错误信息（503 + 原因），不得静默降级为直接 PTY 模式。
- Limpet tmux 配置文件独立提供（escape-time 调低保证 Esc 响应、加大 history-limit、关闭影响单客户端尺寸的选项），配置内容属于实现细节，行为约束是：Esc 响应无明显延迟、回滚行数 ≥ 10000、会话尺寸跟随唯一客户端。
- 直接 PTY 模式退役，无兼容层：个人项目、现存会话均为临时测试会话，切换允许瞬时不可用。
- 名称校验在服务端执行；前端做同规则的即时提示。
- 交互不得依赖 hover；主要触达目标 ≥ 44×44；弹层与软键盘协同（输入元素不被遮挡）。
- 生命周期语义：**会话创建即常驻（无预留 TTL——创建即出现在列表，可关闭）**；断线回收的是接入占用（claimed），会话持续到显式关闭或 Shell 退出；spawn 失败与提前断开清理接入占用；exit 关闭监视器；双接入 409。
- 接入启动流程为异步：首条尺寸与兜底定时器只触发启动，读循环保持能读，断线即时取消捕获并释放占用。

## 非目标

- 任务台账/持久化任务存储、通知（审批等待提醒）、聊天 UI、app-server/harness 协议集成。
- 多客户端同时接入同一会话（tmux 支持但尺寸语义复杂，显式不做）。
- 会话跨 tmux socket 迁移、tmux window/pane 的创建与管理。
- 权限体系（仍仅限本人）。
- PWA/离线缓存、桌面安装外壳、桌面专属交互（右键菜单等）。

## 验收标准

1. 新建命名会话后，列表立即出现该会话；接入后看到 Shell 提示符，目录为默认。
2. 接入状态打开 vim → 关闭页面 → 重新接入：vim 界面原样恢复，期间无输出丢失。
3. 在终端内运行长输出命令后立即断开，数秒后重新接入：断开期间产生的输出在接续首屏可见，且接入后**直接向上滚动**可见断开前的历史行（含颜色），无需进入 copy mode。
4. Shell 内 `exit`：列表中该会话消失；对已消失会话接入返回 404。
5. 列表关闭某会话：Shell 终止（进程消失），列表移除。
6. 重命名后列表与接入地址使用新名；重名返回 409；非法字符（`:` `.`）被拒绝。
7. 同会话第二个 WS 客户端 409。
8. 重启 Go 服务：列表完整恢复，接入任一会话画面如常（tmux 常驻）。
9. 全部现有帧级协议测试（ready 先于输出、首条尺寸决定启动、1008、粘贴、exit、409）在 tmux 模式下保持通过。
10. 手机（蜂窝网络）接入任一会话，可见断开期间状态并可继续操作——对应 charter 第一阶段验收 2/4 的前置。
11. 移动视口（DevTools 375 宽基准）完成全流程：新建（可命名）→ 接入 → 返回列表（后台会话不丢）→ 接入另一会话 → 关闭；全程无 hover 依赖、无遮挡、触达目标达标。
12. 移动按键栏可发送 Esc、Ctrl+C、方向键、Tab、Enter——charter 第一阶段验收 3 的落地，最终以真机验收。
