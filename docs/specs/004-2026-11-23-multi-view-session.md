# Spec 004：会话多视图（N 渲染器 + 尺寸跟随输入者）

- 日期：2026-11-23
- 状态：待评审
- 来源：会话讨论（2026-11-23）：用户两个浏览器页同时打开同一会话被 409 拒绝；提出「后端只传数据、前端负责绘制」。经评估确认——003 的 worker 架构已把唯一事实收进 worker 网格，把前端从「模拟器」降级为「渲染器」是这个架构的自然延伸，单接入不变量随之消解
- 关联：修订 Spec 001/003 的「单接入」不变量（多客户端显式不做 → 多视图成立）；「接管」方案废止（多视图下无意义）；Spec 003 U6 验收整合 hold，待本工作项落地后合并执行

## 背景与决策

单接入不变量的根源：每个前端是一台**独立的终端模拟器**——同一份 PTY 字节流各自解释、各自演化状态、各自把窗口尺寸灌回 PTY（resize 拉锯无解）。003 已把唯一事实收进 worker 的网格；前端本就只是渲染器。本工作项走完最后一步：

**PTY 输出字节流广播给所有接入的渲染器；输入来自任意渲染器；网格尺寸跟随输入者。**

## 语义变更（需要评审确认）

**修订一：单接入废止，多视图成立。** 同一会话 N 个浏览器同时接入（N 条 WS、各自一条到 worker 的连接），不再有 409。任一 viewer 断开重连互不影响；worker 退出才终结所有 viewer（全部收 1000）。

**修订二：尺寸跟随输入者。** 接入者向 worker 申报自己的窗口尺寸（信息性，不触发 resize）；**输入发生时**，若发送者的窗口尺寸 ≠ 当前网格尺寸，网格与 PTY 调整为该尺寸——打字者的视图永远与网格一致。未打字的观察者：窗口与网格不一致时，画面按其自身宽度折行/裁切（看日志可读；全屏应用会乱）——**输入一次即接管尺寸**。观察者断开不回退尺寸（网格保持最后输入者的尺寸，直到下一人输入）。

**修订三：接入即重建，尺寸不再阻塞任何事。** viewer 接入后立即收到重建画面（按网格当前尺寸）+ 实时尾巴；001 的「等首条尺寸（3s/query 兜底）」时序废止——尺寸只在「输入者晋升」时起作用，不需要在任何时机等待。query 兜底与 initTimeout 删除。

## Worker 契约（变更）

- **viewer**：一条 attach 连接 = 一个 viewer。worker 保存其连接、有界输出队列与窗口尺寸（申报值）。不再有独占位/CAS/409。
- **广播**：PTY 输出批次 → 逐 viewer 入队（各自有界）。慢 viewer 打满队列 → 仅丢弃该 viewer（DETACH 4001），其余与会话不受影响。
- **输入与晋升**：任意 viewer 的 INPUT 字节 → PTY；若该 viewer 申报尺寸 ≠ 网格尺寸 → 网格与 PTY 调整为该尺寸（每次输入批次至多一次调整；尺寸相同跳过——无 resize 风暴）。
- **重建**：viewer 接入即重建（formatter，按网格当前尺寸）+ 实时尾巴——与尺寸解耦。断线重连的「恰好一次」断言（003 验收 15）原样沿用。
- **协议**：ftResize 语义变更为「窗口尺寸申报」（帧格式不变）。worker 侧协议版本递增；server 对**旧版本 worker** 适配旧语义（接入时以接入者尺寸合成一次 resize 触发其重建，后续申报照发 = 旧的 resize 跟随接入者行为）——升级窗口内行为正确（spec 003 验收 9 的升级场景继续成立）。握手应答已携带 worker 版本，server 据此分派。

## server / 前端

- server：删除 busy 预检与 409；同一会话多条 WS 中继并存；list 的 `attached` = viewer 数 > 0。
- **前端零改动**：现有 H5 的行为（初始化时上报窗口尺寸、onresize 上报、typing 直接发）在新语义下全部成立。可选打磨（非本工作项）：4001 关闭时状态徽标显示「输出过快」而非「已断开」。

## 已知限制（v1 明示）

- **查询应答重复**：程序查询（如光标位置报告）随字节流到达所有 viewer，每个浏览器的 ghostty 都会应答，程序可能收到 N 份应答（多余应答作为输入垃圾到达）。单 viewer 场景不受影响；去重（首答后吞同内容应答）留待后续。
- **观察者视图折行/裁切**：窗口 ≠ 网格时的固有行为（一块网格只有一个尺寸；全屏应用的布局不可能按旁观者重排）。完美 per-viewer 渲染（RenderState 脏行 → VT + 裁切视图）留待后续增强。
- 观察者断开不回退尺寸。

## 非目标

- per-viewer 独立尺寸渲染（一块网格一个尺寸是事实，不做按 viewer 重排）。
- 查询应答去重、观察者输入抑制。
- 接管（新踢旧）语义：被多视图取代，不实施。
- 广播的画面级权限（只看不打的只读 viewer）。

## 验收标准

1. 同一会话两个浏览器同时接入：均 ready、均实时输出，互不踢、无 409。
2. 任一 viewer 输入：PTY 收到该输入；所有 viewer 画面同步演化。
3. 尺寸跟随输入者：甲（100×30）打字 → 网格 100×30；乙（41×80）打字 → 网格 41×80；甲的观察视图按其窗口折行（已知行为，非缺陷）。
4. 第三、第四个 viewer 接入同样成功；制造高吞吐输出并暂停其中一个的读取：该 viewer 被以 4001 丢弃，其余 viewer 与会话不受影响。
5. 任一 viewer 断开重连：重建 + 实时尾巴，行恰好出现一次、无缺口（003 验收 15 断言原样沿用）。
6. worker 退出（Shell 内 exit）：所有 viewer 同时收 1000；列表移除；录制完整。
7. 回归全绿：粘贴 md5、备用屏重连、关闭回收、U3 三重启场景（语义适配后）；-race 干净。
8. 版本适配：新 server 对升级窗口内的旧 worker（v1）——接入触发其重建、申报照发（旧语义）；新 worker（v2）——申报 + 输入晋升。升级重启后多视图在新 worker 上成立。
9. 前端零改动验证：现有 H5 两个窗口同时打开同一会话全流程可用（含移动视口 375）。
